Demo run-sheet

The whole sequence, in order, with every tap named — and every point where a person has to do something called out before you get there.

Verified against the live dev database · every quoted line re-checked against the app's real strings · startup sequence rehearsed cold from a dead machine · 25 August 2026

The one thing to remember

The strongest moment in this demo is not the app paying out. It is the app refusing to pay out, in plain English, because it could not read the price — and then a named person deciding it on the record. That is the product. Lead with it.

Ten minutes beforeWhat to start, in this order

Rehearsed cold on 25 August from a completely dead machine — Docker quit, Postgres stopped, backend killed, Expo killed. Every timing below was measured, not estimated. The work adds up to about thirty seconds; the reason to allow ten minutes is the one trap in step 1, which cost over ten on the rehearsal.

The branch matters — check it first

Everything the demo shows lives on main as of 25 August. If you are on any other branch, the app you start is not the app in this document.

cd ~/FAYR-Review-Verifier
git branch --show-current

It must say main. If it does not, git checkout main before you start anything below.

1
You · terminal

Docker — and the trap that eats ten minutes

docker info > /dev/null 2>&1 && echo UP || echo DOWN
If it says UP
Nothing to do. Go to step 2.
If it says DOWN
Do not just click the Docker icon. Run these two lines, in this order: 
pkill -f "Docker Desktop"; pkill -f "com.docker.backend"
open -a Docker
Then wait for docker info to answer UP. On the rehearsal that took 10 seconds.
Why the kill first
Docker Desktop can sit in a half-dead state where the app is running but its engine is not — and because macOS already considers the app open, open -a Docker does nothing at all. On the rehearsal that state was waited out for ten minutes with no engine and no error. Killing both processes first is what makes the relaunch actually relaunch. If you find yourself waiting more than about thirty seconds, you are in this state: kill and reopen.
2
You · terminal

The database

docker start fayr-postgres
docker exec fayr-postgres pg_isready -U fayr
Look for
/var/run/postgresql:5432 - accepting connections. Measured: 2 seconds.
If it fails
If the error mentions the daemon, you are back in step 1. If it says no such container, the container was deleted — that is a rebuild, not a restart, and not something to do in the ten minutes before a demo.
3
You · terminal

Migrations, then the seed — the seed is not optional

cd backend
npx prisma migrate deploy
npx prisma db seed
Look for
No pending migrations to apply. then the seed's own list, ending topped up the unbought claim’s purchase deadline. Measured: 2 seconds and 6 seconds.
Run the seed even though nothing looks broken
One of the four product states on the demo account is a claim that has not been bought yet, and a claim expires seven days after it is made. The hourly maintenance sweep then closes it and hands the tickets back — so on any morning more than a week after the database was last seeded, that state is simply gone from the app with nothing on screen to say why. Running the seed pushes that deadline back out to a full week. It is safe to run any number of times: everything else is either already there or skipped, and it says which.
If it fails
The seed refuses outright on any database not named *_dev or *_test — that is deliberate, since it writes users, tasks and ledger entries. Any other failure names what it could not do; nothing is half-applied that a second run will not finish.
4
You · terminal

The backend

npm run start:dev
Look for, at the very end
Fayr backend listening on http://0.0.0.0:3000. Measured: 5 seconds.
The text-message line is ABOVE the route list, not below it
This is the one line that decides whether a real code reaches a real phone, and it prints before the ninety-odd route lines — by the time booting finishes it has scrolled off the top. Scroll back up, or run npm run start:dev | grep -i "active sender" instead. The line reads: 
Active sender: TWILIO — real SMS will be sent to real phones
Do not search for [SmsSender]. That bracketed form appears nowhere in this log — the component name is at the end of the line as {"context":"SmsSender"}, so searching for the bracket finds nothing and reads as though the line is missing.
Check this, it matters
If that line says DEV instead of TWILIO, no real text will be sent and the code only appears in this terminal. Stop and fix it before anyone is watching.
If it fails
A missing or malformed credential makes it refuse to boot and name the variable — read the message, it tells you which one. EADDRINUSE means an old backend is still alive: pkill -f "nest start" and start again.
5
You · terminal

The phone app — in a NEW terminal, from the repo root

cd ~/FAYR-Review-Verifier
npx expo start
Do not reuse the backend's terminal
Step 3 left that one inside backend/, and npx expo start run from there does not fail — it quietly starts the backend folder as if it were the phone app, prints Starting project at …/backend, and rewrites backend/tsconfig.json on its way past. That happened on the rehearsal and had to be undone with git checkout backend/tsconfig.json. Check the Starting project at line names the repo root, not backend.
Look for
Starting project at /Users/…/FAYR-Review-Verifier, then env: export EXPO_PUBLIC_FAYR_API_BASE, then the QR code. Measured: 4 seconds.
Then
Scan the QR code with the phone. Same Wi-Fi as the laptop.
Ignore this warning
It lists three packages as slightly behind (expo, expo-file-system, react-native-svg) and says the project "may not work correctly". It works; this is not the week to change versions.
If the app cannot reach the backend
That env: export EXPO_PUBLIC_FAYR_API_BASE line means .env.local is already supplying your LAN address, which is the normal case. If it is missing, put your LAN address there as EXPO_PUBLIC_FAYR_API_BASE and restart Expo — the override always wins. The name matters: EXPO_PUBLIC_API_BASE without FAYR is read by nothing, so Expo restarts and the app still cannot connect.

The runSign in to money in the wallet

Read this before you touch the phone

Sign in with the number that owns the demo data. Any other number creates a brand-new empty account — the offers still load, but every screen after the claim is blank, and there is no recovering that in the room.

We are on a Twilio trial, so a code can only be delivered to a verified number. Yours is verified. A director's is not, and cannot be added on the spot.

You · phone

Open the app and get to the sign-in screen

On screen
The fayr. splash, then the sign-in landing. Tap through.
The three onboarding cards may not appear
They are shown once per install, not once per account, so a handset that has run this app before goes straight from the splash to sign-in. Both are correct. If you want them on the projector, delete the app and reinstall before the room fills — do not go looking for them live.
If it fails
A blank white screen means the fonts or the bundle did not load — shake the phone, tap Reload.
9
You · phone

Enter your mobile number and tap through

On screen
Six empty boxes, and a line telling you a code is on its way.
What happens
A real SMS arrives on the handset in the room. On iOS the keyboard usually offers the code above it — one tap fills all six boxes at once. Typing it works exactly as well.
Say this while you wait
"This is a real text message to a real number — there is no shortcut wired in behind it."
If no code arrives
Wait for the resend timer, then tap resend once. The code is not in the terminal. The real sender logs a masked number and a provider reference and never the code itself, so there is no way to read it off the screen behind you — if the text does not arrive, the fallback is to stop the backend, set SMS_PROVIDER=dev, restart it, and request a new code, which the terminal then prints. Say you are switching to the offline sender; do not pretend a text arrived.
Two limits, and they are different
The five-attempt lock counts wrong codes on one challenge, not resends. Resending too soon just gets a cooldown and the app only offers the link once its timer reaches zero. Each resend does issue a new code, so an earlier text stops working — use the newest one.

The app

The setup questions run — this account has not done them yet

On screen, in order
Seven screens, and there are three questions, not one. Seven only while this account has answered nothing: answer one question in a rehearsal and the intro drops out, leaving six and changing the first line to "Pick up where you left off". Re-check with the pre-flight if you rehearse.
1 · "Let's set up your profile" — "Takes about 30 seconds — so we can show you campaigns worth your time.", button LET'S GO.
2 · STEP 1/3 "How Young Are you?" — an age band, then a Gender chip. Both are required.
3 · STEP 2/3 "What do you love shopping?" — categories. At least three. The button goes grey below three but it is still tappable: tapping it raises "Pick at least 3 categories to continue." Do not say "it won't let you" and then tap it.
4 · STEP 3/3 "Where do you shop the most?" — marketplaces. There is no minimum here — Next is live with none selected. Pick one or two and say nothing about a requirement; if asked directly, it is optional today.
5 · "Lastly / What shall we Call You?" — your name.
6 · "Finding <first two categories> campaigns for you…" — only the first two you picked, joined by "&", so with three chosen one is not named. It spins and moves on by itself and says "Auto-advances — no tap needed." This is the one screen with no Do this later link; nothing is stuck, it advances in about two seconds.
7 · "Before your first campaign" — three cards: claims and slots, honest reviews only, and know the risk. The third is the warning that a marketplace may act on rewarded reviews.
Worth pointing at
The button on that last card reads I UNDERSTAND — CONTINUE, and pressing it is what records the consent: which version, and the exact time. Not a tickbox that vanishes.
Do NOT tap "Do this later" on the last card
Six of the seven screens carry that escape (the spinner does not) and answers already given are kept — but the last one is where consent is written, so skipping it leaves no consent on record. Tap the button.
If it fails
If it loops back to the intro, tap Do this later and carry on — the feed is the next screen either way.

You · phone

Claim an offer from the feed — four screens, not one tap

The offer is the Amazon 5-layer vegetable rack, ₹2,222 at 90%. Do not scan the feed for "Spin Your Storage" — that is the internal campaign name and it is on no screen. The card reads "Amazon Brand - Solimo 5-Layer Revolving Vegetable Kitchen Rack…" and it is the 8th card down, so scroll rather than hunt.

Why that one
It is the only active offer this account has never claimed. Every other card already has a task, so tapping one opens the existing task instead of a fresh claim — correct behaviour, wrong story.
The tap order, in full

1 · The feed card. Green chip 90% Refund · up to ₹1,999, footer Claim · 5 tickets and Claim →. Tap it.
2 · The product page. Sections run Campaign overview · How it works · What to buy · Terms & conditions · Frequently asked. The button at the bottom reads Claim campaign · 5 tickets → with "Claiming reserves this product for you" under it. Tap it. Nothing is spent yet.
3 · "Confirm participation". This is new and it is where the tickets actually go. Four cards: the product, Your refund (Refund — 90% of what you pay, Maximum — ₹1,999), Tickets (This claim uses 5 tickets, Your balance after 35 tickets), and Deadline — "Buy the product within 7 days of joining."
Tick the box first. "I'll write an honest review. I understand my rating never affects my refund." CONFIRM & JOIN stays grey and does nothing until it is ticked. Then tap it.
4 · "Product Claimed!" — a sheet with "This product is yours until <date and time>. Buy it on Amazon before then.", a chip reading 🎟 5 tickets held · returned if the claim expires, and a countdown box showing 6d 23h · Remaining.
Do NOT tap the big green button
"Go to Amazon →" opens Amazon's real website inside the app. Tap the quiet grey link underneath instead — "I'll buy in a bit" — which lands you on the task. This is the one place in the run where the most obvious button is the wrong one.
Say this at the honesty tick
"This is the moment the tickets are spent, so it is the moment we ask for something back: not a five-star promise, an honest one. The rating never changes the refund, and that sentence is on the screen where it costs us something to say it."
Say this at the deadline
"Seven days to buy, and that is the real number — the server sets the clock when the claim is created, and the same clock returns the tickets automatically if the purchase never happens."
What the task screen says
Its header is Task status. It does not say "Purchase pending" — that phrase is a chip in the My Products list, one screen away. Say "the task opens at the buy step", not the phrase.
Do not
Try to actually buy it. See Not yet for the sentence to use.
If the claim is refused
You land on a screen headed "Something went wrong" with the server's own reason printed underneath — so read the small line, not the headline. "You've already completed this campaign" there means you picked a card with a finished task: tap Back to campaign and use the vegetable rack.

Be straight about thisWhat not to demo, and what to say

Every line below is something a sharp person in the room might reach for. Saying it first is stronger than being caught by it.

Don'tBecauseSay
Buy a product live The purchase happens in the marketplace's own app, and it takes days to deliver. "The purchase happens on Amazon, in their app, with their payment. We verify it afterwards from their own pages — we are never in the middle of the transaction."
Send a code to anyone else's phone Twilio trial: only verified numbers, five of them ever, and the trial expires 30 days after it was opened. "Texting is on a trial account today. Production needs Indian DLT registration — that is paperwork and a company entity, not engineering."
Promise marketing texts Without DLT we can only send a code the user just asked for, and the route can be suspended without notice. "One-time codes the user triggered, and nothing else. That is a deliberate limit, not an oversight."
Meesho or Myntra The Meesho reader is next on the list. Myntra is deliberately dormant — not a partner right now, code left intact. "Amazon and Flipkart first, quick-commerce behind them. Meesho is the next reader. Myntra is parked on purpose."
Lead with the screenshot upload It works, but it is the lowest tier of evidence and never approves itself. "A screenshot can be doctored and still read perfectly, so it is supporting evidence only — it never releases money on its own."
Quote the "paid out" total in Reports It is summed from the withdrawals table, while the ledger's payout account has no matching entry when a transfer is marked paid. The two cannot agree yet. "Reconciliation between the payout ledger and the withdrawal records is a known open item. I would rather show you the gap than a tidy number I cannot defend."
Wait for the automatic release The scheduled release exists, but standing on stage waiting for a timer is a bad minute. "Releases also run on a schedule; I am doing it by hand so you can see the moment."
Offer to delete the account Account deletion is not built. "Deletion and data export are on the compliance list, not built yet."
Sign in on a second device mid-demo One account holds all the prepared data, and a second sign-in is a second live code. Nothing — just don't offer.
If someone asks "what stops a staff member just paying their friend?"

Say: every figure a person types is capped by the order's own total, needs a named source and a written note, is logged against that named account with the previous value beside it, and cannot overwrite anything the marketplace itself told us. And the person who sets the amount is not the person who approves the transfer. Then say the honest part: nothing yet stops the same admin doing both jobs — role separation is enforced, one person holding two roles is not.
