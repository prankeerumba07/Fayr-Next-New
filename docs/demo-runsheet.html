Demo run-sheet

The whole sequence, in order, with every tap named — and every point where a person has to do something called out before you get there.

Verified against the live dev database · 20 August 2026

The one thing to remember

The strongest moment in this demo is not the app paying out. It is the app refusing to pay out, in plain English, because it could not read the price — and then a named person deciding it on the record. That is the product. Lead with it.

Thirty minutes beforeWhat to start, in this order

Four windows. Start them in order; each one needs the one above it.

1
You · terminal

The database

docker start fayr-postgres
docker exec fayr-postgres pg_isready -U fayr
Look for
accepting connections.
If it fails
Docker Desktop is not running — open it, wait for the whale to stop animating, run both lines again.
2
You · terminal

The backend

cd backend
npm run start:dev
Look for
Nest's route list, then one line naming the text-message provider: [SmsSender:twilio].
Check this, it matters
If that line says dev instead of twilio, no real text will be sent and the code only appears in this terminal. Stop and fix it before anyone is watching.
If it fails
A missing or malformed credential makes it refuse to boot and name the variable — read the message, it tells you which one.
3
You · terminal

The phone app

npx expo start
Then
Scan the QR code with the phone. Same Wi-Fi as the laptop.
Look for
One startup line in the Expo log naming the backend address the app resolved. It should be your laptop's LAN address, not localhost.
If it fails
If the app cannot reach the backend, put your LAN address in .env.local at the repo root as EXPO_PUBLIC_API_BASE and restart Expo — the override always wins.
4
You · browser

The staff console

Open admin-panel/index.html in the browser — double-clicking the file is enough, it talks to http://localhost:3000 on its own.

Sign in with
The ADMIN account — the address in STAFF_BOOTSTRAP_EMAIL. ADMIN sees every queue, so one login runs the whole demo.
Look for
The sidebar, and a badge reading 5 next to Unit counts.
If it fails
"Can't reach the Fayr server" means step 2 is not running. A wrong password locks nothing — just retype it.
5
You · terminal

The pre-flight check — the one command that proves the demo is intact

cd backend
npx ts-node scripts/check-awaiting-amount.ts
Look for
Refunds held for a person to decide: 5, then five lines — Flipkart and Amazon needing a count, Blinkit, Instamart and Zepto needing an amount.
Why bother
This reads the real database through the real code. If it says 5, every step below will behave as written.
If it says something else
Somebody already cleared one of these on a previous run. The demo still works — just use whichever held task is still listed, and take its figure from the table below.

The runSign in to money in the wallet

Read this before you touch the phone

Sign in with the number that owns the demo data. Any other number creates a brand-new empty account — the offers still load, but every screen after the claim is blank, and there is no recovering that in the room.

We are on a Twilio trial, so a code can only be delivered to a verified number. Yours is verified. A director's is not, and cannot be added on the spot.

6
You · phone

Open the app and get to the sign-in screen

On screen
The fayr. splash, then the onboarding cards, then the sign-in landing. Tap through.
If it fails
A blank white screen means the fonts or the bundle did not load — shake the phone, tap Reload.
7
You · phone

Enter your mobile number and tap through

On screen
Six empty boxes, and a line telling you a code is on its way.
What happens
A real SMS arrives on the handset in the room. On iOS the keyboard usually offers the code above it — one tap fills all six boxes at once. Typing it works exactly as well.
Say this while you wait
"This is a real text message to a real number — there is no shortcut wired in behind it."
If no code arrives
Wait for the resend timer, tap resend once. Still nothing: read the code out of the backend terminal — it is logged as sent, not printed — and say the network is slow. Do not tap resend repeatedly; there is a lock after five wrong attempts.
8
The app

The setup questions run — this account has not done them yet

On screen, in order
An intro card · pick your shopping categories (at least three, the button stays off until then) · your name · a "building your feed" moment · a short "how Fayr works" card.
Worth pointing at
The terms acceptance here is recorded — which version, and the exact time. Not a tickbox that vanishes.
If you want to skip it
Every one of these screens has Do this later. Answers already given are kept.
If it fails
If it loops back to the intro, tap Do this later and carry on — the feed is the next screen either way.
9
You · phone

Claim an offer from the feed

Use "Spin Your Storage — 5-Layer Vegetable Rack" on Amazon, ₹2,222 at 90%.

Why that one
It is the only active offer this account has never claimed. The others already have a task, so tapping them shows the existing one instead of a fresh claim — which is correct behaviour but not the story you are telling.
On screen
The offer detail with the product, the percentage back, and the ticket cost. After claiming: your ticket count drops by 5, and the task opens at Purchase pending.
Do not
Try to actually buy it. See Not yet for the sentence to use.
If it fails
"You've already completed this campaign" means you picked one with a finished task — back out and use the vegetable rack.
10
You · phone

Now open the Blinkit task — Chrysanthemum Flower Pot

Find it under My Products. This is the centre of the demo.

On screen
The timeline is almost entirely done: bought, delivered, review written, review publicly live, return window closed. And it still says Refund on hold.
The words it shows
"We could not read the price you paid, so a person at Fayr will confirm it before your refund is paid. Nothing is lost and you do not need to do anything."
Say this
"Blinkit's order page gives us a basket total and no line price. We will not divide a basket to guess what one item cost, so this stops here and waits for a human. No enum on the screen, no dead end, and nothing lost."
If it fails
If the task shows nothing, pull down to refresh. If it still looks empty, you signed in with the wrong number.
Stop — a person has to act now

Nothing else moves until a staff member decides the amount. Turn to the browser. This hand-off is the demo — do not apologise for it.

11
Staff · console

Open Unit counts in the sidebar and find the Blinkit card

On screen
Five cards. The Blinkit one asks for an amount and shows the order number, the order total, what the offer says the product costs, and the ceiling: "Most this can be: ₹604.00 — the order's own total".
Say this
"The reviewer cannot type any number they like. One item cannot have cost more than the whole order did, so that is the ceiling — derived from the order, not a round number somebody picked."
If the queue is empty
Refresh the browser. If it is still empty, you are signed in as FINANCE or OPERATIONS — this queue is SUPPORT and ADMIN only.
12
Staff · console

Fill in the three fields and watch the preview line

  • What one unit cost: 599
  • Where you read it: "The marketplace order page"
  • What you saw: type a real sentence — "order page lists the pot at ₹599"
On screen
Under the fields: "This pays ₹539.10 — 90% of ₹599.00", worked out by the server using the same calculation that will actually pay it.
Say this
"Where it came from is a fixed list, not free text — somewhere another person can go and check. If this payout is ever disputed, 'they typed 599' is not a defence; 'they read it off the order page, and here is their note' is."
Then
Tap Confirm amount. The card stays, marked just decided, so a mistyped figure can still be corrected.
If it refuses
A red line under the form says exactly why — most likely the note is too short, or the figure is above the ceiling. Fix and retry; nothing is lost.
13
You · phone

Back to the phone. Pull down to refresh the Blinkit task

On screen
The hold message is gone. In its place: Release ₹539.10 to wallet.
Say this
"The reviewer never touched the money. They answered one question, and the same rule that was blocking the payout now allows it."
If the button does not appear
Refresh again — the phone re-reads the task from the server, not from its own memory. Still nothing: the panel refused the save; check step 12.
14
Money moves

Tap Release ₹539.10 to wallet

On screen
The task closes as refunded. Open Earnings: the wallet is ₹539.10, up from zero, and All Time Earnings reads the same.
Say this
"That is a double-entry ledger entry in whole paise. Nothing is a floating-point number anywhere near the money."
If it fails
A message naming what is still missing — the return window, the review, or the amount — appears in plain words. Read it out; it is written to be read out.
15
You · phone, then console

Optional finish: take the money out

On the phone
Wallet → Withdraw. The minimum is ₹100 and a payout destination is already saved, so it goes through.
In the console
Withdrawals queue → Approve → Mark paid. That queue is FINANCE and ADMIN — a different person from the one who set the amount.
Say this
"Deciding the amount and releasing the money are different jobs held by different roles. Neither one can do the other's."
If it fails
"You need at least ₹100 in your wallet to withdraw" means the release in step 14 did not land. Go back one step.

If you have more timeThe two moments worth adding

16
Staff · console

The count decision, on the Amazon garment rack

Same queue, the 920244c9 card. It asks for a count, not an amount, and it says why: the order page did not state one.

Enter
1, with a note. The preview says it pays ₹797.30.
Say this
"A refund is for one unit. If the page does not say how many units were bought, we do not assume one — three units at a third of the price look identical on a receipt."
Expect this next — it is a feature, not a fault

After you set the count, the app will still not release that one. The ₹938 actually paid is well below the ₹1,331 the offer quotes, so the app asks the person who bought it to stand behind the order first.

17
You · phone

Tap Yes, this is my order on the Amazon task, then release

On screen before you tap
Under Refund on hold: "the amount you paid doesn't match this offer — confirm this is your order".
Say this
"The price moved between us writing the offer and them buying it. That is usually a discount and it is fine — but we ask the buyer to confirm it is their order before we pay against a number that does not match."
Then
The release button appears with ₹797.30 on it.
If it fails
If the button is greyed out it is already sending — wait two seconds rather than tapping again.

Be straight about thisWhat not to demo, and what to say

Every line below is something a sharp person in the room might reach for. Saying it first is stronger than being caught by it.

Don'tBecauseSay
Buy a product live The purchase happens in the marketplace's own app, and it takes days to deliver. "The purchase happens on Amazon, in their app, with their payment. We verify it afterwards from their own pages — we are never in the middle of the transaction."
Send a code to anyone else's phone Twilio trial: only verified numbers, five of them ever, and the trial expires 30 days after it was opened. "Texting is on a trial account today. Production needs Indian DLT registration — that is paperwork and a company entity, not engineering."
Promise marketing texts Without DLT we can only send a code the user just asked for, and the route can be suspended without notice. "One-time codes the user triggered, and nothing else. That is a deliberate limit, not an oversight."
Meesho or Myntra The Meesho reader is next on the list. Myntra is deliberately dormant — not a partner right now, code left intact. "Amazon and Flipkart first, quick-commerce behind them. Meesho is the next reader. Myntra is parked on purpose."
Lead with the screenshot upload It works, but it is the lowest tier of evidence and never approves itself. "A screenshot can be doctored and still read perfectly, so it is supporting evidence only — it never releases money on its own."
Quote the "paid out" total in Reports It is summed from the withdrawals table, while the ledger's payout account has no matching entry when a transfer is marked paid. The two cannot agree yet. "Reconciliation between the payout ledger and the withdrawal records is a known open item. I would rather show you the gap than a tidy number I cannot defend."
Wait for the automatic release The scheduled release exists, but standing on stage waiting for a timer is a bad minute. "Releases also run on a schedule; I am doing it by hand so you can see the moment."
Offer to delete the account Account deletion is not built. "Deletion and data export are on the compliance list, not built yet."
Sign in on a second device mid-demo One account holds all the prepared data, and a second sign-in is a second live code. Nothing — just don't offer.
If someone asks "what stops a staff member just paying their friend?"

Say: every figure a person types is capped by the order's own total, needs a named source and a written note, is logged against that named account with the previous value beside it, and cannot overwrite anything the marketplace itself told us. And the person who sets the amount is not the person who approves the transfer. Then say the honest part: nothing yet stops the same admin doing both jobs — role separation is enforced, one person holding two roles is not.
